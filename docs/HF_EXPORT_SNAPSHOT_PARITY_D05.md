# D05 HF-style export snapshot safety and runtime parity

## Scope

This package closes the remaining D05 conversion-integrity gap after the exact-green S0 successor composition and D02 repeatability proof.

It does **not** replace D01 model logic, D04 tokenization, D05 checkpoint-v1, D07 generation/sampling, D06 stage gates, D08 locks, or D10 promotion authority. It composes those accepted contracts.

## Defects closed

The previous HF-style export path verified the checkpoint and then reopened `weights.safetensors` and `manifest.json` by pathname for `shutil.copy2`. That left a verify-to-copy race even though checkpoint loading had already been hardened to consume one immutable verified snapshot.

The previous `overwrite=True` path also recursively deleted an existing export before creating the replacement. A process/filesystem failure in that interval could destroy the last valid export.

The repaired path now:

1. calls `prepare_checkpoint_load()` once to obtain verified checkpoint bytes;
2. writes `model.safetensors` and the copied checkpoint manifest from that verified byte snapshot, not by reopening source payload paths;
3. stages the complete export in a sibling temporary directory;
4. writes config, attestation and parity-request metadata in staging;
5. verifies the staged directory against a valid source checkpoint before publication;
6. atomically publishes only to a previously nonexistent destination;
7. treats existing export directories as immutable even when legacy callers pass `overwrite=True`;
8. deletes staging after any failure so no partial destination is published.

Published export verification enforces an exact five-file inventory, rejects symlink/non-regular files, requires exact source-manifest bytes and exact canonical weight bytes, and checks every attestation/parity-request hash and identity field.

## Runtime parity

`python -m twelve_six.inference.hf_export_parity` is the D05->D07 conversion evidence path.

It first loads the canonical checkpoint through the existing first-party D01+D04+D05 adapter. It then verifies the HF-style directory against that checkpoint, decodes only the already-verified exported `model.safetensors` bytes into a fresh D01 model, and invokes the existing D07 parity harness.

The evidence requires exact zero tolerance:

- prompt token IDs equal;
- context/EOS contracts equal;
- every compared next-token logit equal (`atol=0`, `rtol=0`);
- every greedy token equal;
- decoded generated text equal.

Example:

```bash
python -m twelve_six.inference.hf_export_parity \
  --checkpoint /path/to/checkpoint \
  --export /path/to/hf-export \
  --prompt "12-6" \
  --prompt "Україна" \
  --max-new-tokens 8 \
  --output hf-export-parity.json \
  --json
```

Prompt text is not written into the parity evidence; only SHA-256 prompt identities are recorded.

## Truth boundary

A passing report means the **12-6 native runtime** loaded from the exported SafeTensors bytes is exactly equivalent to canonical checkpoint inference for the tested prompts and steps.

It does **not** mean `transformers.AutoModel` understands this architecture. `transformers_architecture` remains `NOT_CLAIMED`. It does not establish vLLM, GGUF, llama.cpp, Windows/NVDA live runtime, GPU, mixed-precision or distributed parity.

The export attestation deliberately retains `runtime_logit_generation_parity=NOT_TESTED`; runtime evidence is a separate candidate-bound artifact generated by the parity harness. This avoids turning a copy-time assertion into a runtime compatibility claim.

Canonical Base remains random-initialized and pretraining-only. No instruction/alignment/refusal/personality/domain-specialization behavior, foreign pretrained weights, paid compute, audit verdict, CANDIDATE or STABLE promotion is introduced.
