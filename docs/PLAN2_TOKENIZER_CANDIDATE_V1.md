# Plan 2 Section 11 — tokenizer candidate architecture (LOCAL_FREE)

This component reuses the canonical byte tokenizer (exact Git blob pinned) and does NOT add a second training/runtime/token-ID authority. Two architecture specs are compared: incumbent lossless 256-byte baseline and prospective byte-level BPE with a 32,768-vocabulary target, normalization=none, Unicode lossless byte fallback and four prospective unassigned special-token names. No IDs, vocabulary or merges are frozen here.

A six-sample versioned/pinned handwritten fixture covers Ukrainian, English, Python code, mixed language/code, Unicode normalization boundaries, NUL, CRLF, astral characters and literal special-token strings. Tiny human-authored merge sequences model only a **fixture compression proxy**; they are **not fitted BPE merges, real tokenizer compression or a benchmark**. The recommendation is for future Section 12 fit/evaluation, not approved for training or inference. The stage saves candidate architecture hashes, per-sample UTF-8/source-text hashes, byte/proxy counts and deterministic recommendation in an immutable JSON manifest; it never stores source text in evidence.

Independent tests: PYTHONPATH=src:. pytest -q tests/test_plan2_tokenizer_candidates_v1.py tests/test_tokenization.py tests/test_tokenizer_migration_compatibility.py; Ruff on new source/tests; CLI restart, clean rebuild and manifest byte-comparison. Negative cases: policy/fixture tamper, forged canonical byte source, duplicate/nonfinite/bad UTF-8 JSON, corrupted manifest, symlink destination. Strict no-fit/no-runtime/no-training/no-checkpoint/no-final-test/no-paid-compute flags are part of manifest.
